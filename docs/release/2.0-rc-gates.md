# FrameByNavin 2.0 — Release Candidate Gates

This checklist freezes feature expansion after Beta 2. It separates gates that CI/schema review can prove from gates that require a production-signed build, external-console configuration, or real-device testing.

## Automated on every v121 RC1-preflight build

- Debug QA build still compiles and remains installable with the stable development key.
- Release APK and Play bundle source sets compile without production signing material in the repository.
- Release build is explicitly non-debuggable.
- FrameByNavin targets Android 16 / API 36 for September 2026 Play-submission eligibility.
- Main activity uses edge-to-edge and source is checked for Android 16 predictive-back legacy interception.
- Release App Check implementation uses Play Integrity.
- Debug App Check implementation remains isolated to the debug source set.
- Cleartext HTTP traffic is disabled by the Android manifest.
- Android backup is disabled; FrameByNavin uses its own versioned backup/restore flow.
- App components remain non-exported except the launcher activity required by Android.
- Firebase API keys are not copied into Kotlin/Java source.
- Supabase service-role/secret keys are forbidden from app source. Only the publishable client key is allowed.
- Supabase production authorization review is recorded in `v120-production-security-data-audit.md`, with the privilege-hardening migration source-controlled.
- Drive access tokens remain process-only and are cleared on account adoption/sign-out so authorization cannot cross account transitions.
- Production signing can be supplied only through external Gradle properties/environment variables; the keystore and passwords are never committed.
- Core regression gates remain: reminder completion safety, Finish Project safety, live Gemini Video Autopsy, Voice Quick Idea, Opportunity Engine placement, and backup recovery code.
- Full debug tests/lint/build plus release lint/APK/AAB compilation must pass before a staging branch is updated.

## Verified production schema gate — PASSED in v120

The production Supabase identity schema was reviewed directly and hardened:

- `creator_profiles` has RLS enabled.
- SELECT/INSERT/UPDATE/DELETE policies bind authenticated access to `auth.uid() = user_id`.
- `claim_creator_username` binds writes to `auth.uid()` and does not accept a target user id.
- `anon` has no privileges on `creator_profiles`.
- `authenticated` has only SELECT, INSERT, UPDATE and DELETE; broad TRUNCATE/REFERENCES/TRIGGER grants were removed.
- Username RPC execution is not exposed to `anon`/`public`.

This closes the Supabase RLS/RPC review requirement for the current production schema. Any future Supabase table/function requires a new authorization review.

## Play target API gate — PASSED in v121

Google Play requires new Android phone/tablet apps and app updates submitted after 31 August 2026 to target Android 16 / API 36 or higher. v121 moves FrameByNavin from API 35 to API 36 and compiles both release APK and AAB paths against the Android 16 SDK.

Physical Android 16 behavior validation still remains part of the device matrix below.

## Must pass before RC1 is called production-ready

### Production signing + Google/Firebase identity

- Create/confirm the production upload/app-signing path (prefer Play App Signing for Play distribution).
- Provide release signing only through external secure values, never repository files/secrets.
- Run `scripts/release-signing-preflight.ps1` and record the production SHA-1 and SHA-256 certificate fingerprints.
- Register those production fingerprints in Google/Firebase configuration.
- Verify Google sign-in and YouTube authorization from the production-signed install.
- Verify Firebase AI with Play Integrity App Check from the production-signed install.
- Enable App Check enforcement only after the production-signed validation succeeds; do not use debug tokens as a release substitute.

### Android 13 / 14 / 15 / 16 device matrix

For at least one physical device per available major Android version:

- Fresh install and upgrade install.
- Notification permission denied / allowed.
- Exact-alarm permission unavailable / denied / allowed where applicable.
- Full-screen intent unavailable / denied / allowed where applicable.
- Battery optimization enabled and disabled.
- Normal notification reminder fires once.
- Voice reminder starts, stops, and does not leave a foreground service running.
- Alarm reminder starts, snoozes, completes, and auto-stops.
- Reboot, timezone change, clock change, and app update recovery reschedule future reminders without completing projects.
- Reminder **Done** changes only the intended reminder/workflow surface and never falsely completes the whole project.
- Android 16: edge-to-edge layout has no clipped controls or inaccessible system-bar content.
- Android 16: predictive back exits/navigates correctly without dead back gestures or accidental project mutation.
- Large-screen/foldable smoke test where available, because Android 16 relaxes orientation/resizability restrictions on large screens.

### Data durability

Test with non-trivial data: active projects, completed projects, reminders, weekly plan, ideas, creator settings, YouTube links/checkpoints, rewards, Project Pulse history, workflow timeline, and personal frames.

- Create local backup; validate preview counts.
- Restore over existing data.
- Force-close during restore and confirm pending-journal recovery on next launch.
- Corrupt checksum and confirm restore is rejected without changing current data.
- Restore an older supported schema.
- Confirm recovery copies remain available after a failed restore.
- Confirm account tokens are not included in creator backups.

### Account + cloud boundaries

Automated/static parts now covered:

- account transitions serialize and invalidate stale operations;
- cached creator profiles from another user are rejected;
- Drive access tokens are process-only/account-bound and cleared on account transition/sign-out;
- empty local state cannot silently snapshot over meaningful Drive history.

Still test on a real install:

- Google/Supabase session refresh succeeds after token expiry.
- Signing out removes the encrypted local session while preserving creator work.
- Switching Google accounts requires fresh Drive authorization and cannot expose the previous account's appDataFolder.
- Drive Vault recovery with empty cloud, valid backup, stale backup, malformed backup and wrong-account scenarios.

## RC1 exit rule

RC1 is allowed only when:

1. v121 automated RC preflight is green,
2. production signing/OAuth/App Check is validated,
3. the Android 13–16 device matrix has no P0/P1 failures on available physical devices,
4. backup/restore destructive-path testing passes,
5. the production Supabase authorization review remains valid,
6. no known regression can lose creator data, falsely complete a project, cross account boundaries, or silently miss a promised reminder.

Feature requests discovered during this phase are recorded for 2.1 unless they fix a release-blocking defect.
