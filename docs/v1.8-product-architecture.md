# FrameByNavin v1.8 Product Architecture

Status: locked product direction for the v1.8 Creator OS transition.

## Product promise

FrameByNavin should work for a creator who is not Navin and who is not necessarily a film creator. The app stays a premium creator control room, but the product language and defaults come from the creator's own profile, projects and connected performance data.

## Primary information architecture

The target primary navigation is:

1. **Today** — the daily command center: current priority, next move, reminders, risks and quick progress.
2. **Ideas** — capture, search, shape and convert ideas into projects.
3. **Create** — active production workspace: projects, workflow steps, focus mode, status and archive.
4. **Calendar** — publishing plan, deadlines, recurring weekly slots and release timing.
5. **Insights** — connected and local performance intelligence, patterns and creator opportunities.

A universal **+ Capture** action remains available above the primary navigation so a creator can save an idea from anywhere without first choosing a destination. New Project belongs inside Create and is also available from relevant empty states and contextual actions.

The existing Control surface remains a secondary utility layer for advanced tools such as Daily Brief, Release Day, reminders, automation, backup and settings. It must not compete with the five primary destinations.

## New-creator journey

### Step 1 — Creator identity

Collect only product context needed to personalize the local Creator OS:
- preferred display name
- creator category

No niche is assumed and the profile is editable later.

### Step 2 — Platforms

Allow multi-select for the platforms the creator actively publishes to. Platform selection will later drive project templates, publishing fields and relevant Insights connections.

### Step 3 — Current goal and publishing target

Collect one current primary goal and a realistic weekly publishing target. The goal is a planning lens, not a permanent identity label.

### Step 4 — Reminder reliability

Offer Android notification, exact timing, full-screen alert and background-reminder setup. These permissions stay optional and editable from Settings.

### Entry state

After onboarding, land on Today. For a creator with no projects, Today should explain the system through one useful next action rather than showing an empty dashboard. The first useful loop is:

**Capture idea → shape idea → create project → work next step → schedule/publish → learn from result.**

## Personalization contract

Creator-selected profile data is stored locally with app settings and included in existing backup/export behavior. It may personalize greetings, defaults, templates and future intelligence, but it must never silently overwrite the creator's explicit project choices.

## v1.8 implementation order

1. Creator identity + onboarding + editable profile.
2. Replace the old Today / Plan / Studio / Insights navigation with Today / Ideas / Create / Calendar / Insights.
3. Make universal Capture distinct from New Project.
4. Build the new Create workspace by combining the useful parts of Plan and Studio.
5. Make Calendar a first-class destination rather than an overlay.
6. Tune Today for a brand-new creator and for an active creator.
7. Extend automated UI tests across the new primary navigation and first-project journey.

## Non-goals for this stage

- AI copilot generation
- multi-user/team collaboration
- mandatory backend account
- paid AI dependencies
- replacing the approved v1.7.5 stable recovery point

The v1.7.5 founder prototype remains frozen and untouched. All v1.8 product work continues on `foundation/v1.8-cleanup` until an explicit new stable candidate is approved.
