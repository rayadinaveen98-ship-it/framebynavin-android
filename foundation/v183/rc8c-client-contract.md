Exactly nine app files. The source archive was independently recovered from verified RC7 and the patch passed local application, scope and whitespace checks. Eleven pure recovery regression tests passed using the installed Kotlin compiler and a local JUnit-compatible assertion harness; authoritative Android tests remain CI-gated.

The client fetches the server lifecycle before creator writes, persists the account-scoped phase/generation, and sends `x-creator-write-epoch` for profile, device, username and backup writes. It uses atomic delete and explicit resume RPCs, never silently retries a stale deletion in a new generation, and preserves legacy RC7 journals without inventing their missing epoch. Unknown/deleted status blocks writes. Restore checks live lifecycle before replacing local data. Reactivation is a separate user-confirmed action, does not restore deleted data, and clears backup approval. The existing offline project system, local creator data, backup schema 5, and manual-only upload policy are retained.

CI must verify the payload, compile/test/lint the app, run API 35 emulator regressions, verify version/signature, then commit canonical source and upload APK/source/diagnostics. Do not promote a failed candidate. RC7 remains the installable baseline and frozen v1.8.2 remains the rollback.

Deployment remains blocked on actual-Supabase schema/RPC/privilege compatibility, two-account authenticated HTTP acceptance, separate-session/legacy-device rollout verification, and a reversible deployment plan. Do not apply the migration or delete any live records during this Android build. RC8c cloud operations intentionally fail closed while the server contract is unavailable. Full Auth-account deletion is not part of this candidate and must not be inferred from creator-data deletion. Physical-device acceptance and production signing/OAuth/privacy gates remain separate.
